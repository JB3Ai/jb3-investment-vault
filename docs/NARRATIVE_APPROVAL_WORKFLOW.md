## Reader integration

`loadApprovedNarratives` in `src/lib/privateContent.ts` uses the existing authentication and two release checks, then requires an exact BRUCE_PRIVATE grant. RLS remains authoritative for grant expiry/revocation and database reads. It queries only approved narratives from `vault_content_records`; no asset download, financial row query, service key or fallback is added. Unexpected classifications, kinds, sections, missing review metadata and unresolved evidence are rejected. Multiple narratives require unique source line references and one source checksum/reference to preserve source order; otherwise the reader reports unavailable.

`AuthenticatedSectionReader` wraps the current `SectionReader` only in secure mode. It clears stale results when the section/account changes, ignores late responses after unmount/sign-out, and supports loading, unavailable, denied and retry states. Narrative strings are rendered as escaped text with preserved whitespace; no HTML or Markdown execution is introduced. The existing reader classes, layout and responsive styles are retained. The secure narrative path does not render synthetic calculators, galleries, timeline or investment modules. Demonstration mode keeps its existing behavior and synthetic registry.

The secure sign-out button is grouped with its access label so it cannot wrap beneath the fixed-height mobile header and become obstructed by the tools row. Console styling and responsive CSS remain unchanged.

The secure console currently still obtains navigation and presentation metadata from the legacy `vault_sections` path and requires a legacy membership. Future setup must provision safe section metadata for this navigation separately from the new narrative records, and give the verified intended account its exact BRUCE_PRIVATE grant. A legacy PRIVATE membership alone does not confer narrative access. The new reader never falls back to a legacy section body. Document-library and executive-briefing delivery remain their existing paths; this change does not make them new canonical master/PDF delivery adapters. The optional laboratory interlude remains a separate draft and is excluded from the wording proposal; its final visual delivery needs its own reviewed integration before any interlude record is approved.
